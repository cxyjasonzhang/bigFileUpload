# ADR-0005：菜单管理模块设计

- 日期：2026-08-18
- 状态：已接受
- 关联：ADR-0004（角色编辑弹窗规范）、CONTEXT.md「菜单树 / 软删除 / 类型联动表单 / 同级交换排序」

## 背景

为 `sys_menu` 表提供管理后台页面，实现菜单的**添加、编辑、删除**功能。菜单数据天然是树形结构（`parent_id` 表达层级），是后续「角色-菜单授权（RBAC）」的数据基础。

## 决策

### 1. 展示形态：树形表格 + 全量加载

- 列表使用 `el-table` 树形模式（`row-key="menuId"` + `tree-props`），支持展开/收起，不启用分页。
- 后端 `GET /menus` 返回**平铺列表**，前端递归组装树。
  - 理由：菜单数据量小（几十条），一次拉全性能无忧；后端保持简单查询风格（与 `roleApi.js` 一致）。

### 2. 删除策略：软删除（与角色管理不同）

- 删除执行 `UPDATE sys_menu SET is_deleted = 1`，**不物理删除**。
- 所有查询必须过滤 `is_deleted = 0`。
- 带子节点的菜单**禁止删除**（后端校验 + 前端提示），避免悬空子树。
- 理由：菜单将被角色授权引用，误删不可恢复成本高；软删除保留数据供未来追溯/恢复。**注意与角色管理（物理删除）不一致是有意为之。**

### 3. 表单：类型联动

- 弹窗顶部 radio 选择 `menu_type`（0目录 / 1菜单 / 2按钮），字段按类型动态显示：
  - 目录：名称、图标、排序（path 可选）
  - 菜单：名称、path、图标、排序（perms 可选）
  - 按钮：名称、perms（必填），path/icon 隐藏
- 父级使用 `el-tree-select` 级联选择，顶级为「根目录（0）」；按钮类型节点不可选为父级。

### 4. 排序：同级交换

- 表单提供 `order_num` 数字输入；操作列提供「上移 / 下移」按钮，仅与**同级兄弟**交换 `order_num`（`parent_id` 相同），不跨层级。

### 5. 搜索：轻量前端过滤

- 顶部关键字（名称）+ 状态筛选，前端在已加载的树数据上过滤，命中子节点时**保留父级链**，避免断头树。
- 菜单管理页不做「查看详情」弹窗，操作列仅含编辑 / 删除 / 上移 / 下移。

### 6. 范围边界

- 本次**不实现**角色-菜单绑定（RBAC），`perms` 字段在表单中正常录入留作后续使用；侧边栏菜单仍由静态 `menuConfig` 驱动。

## 后果

- 新增 `server/routes/menus.js` + `server/db/menuApi.js`，前端新增 `pages/menuManage/`。
- 后端所有菜单查询需带 `WHERE is_deleted = 0`，新增菜单类数据时须遵守。
- 上移/下移交换后 `order_num` 可能出现负数或非连续值，仅用于排序，无业务含义。
