# ADR-0009：用户分配角色设计

- 日期：2026-09-17
- 状态：已接受
- 关联：ADR-0006（RBAC 动态菜单）、CONTEXT.md「用户分配角色」

## 背景

用户管理需要给用户分配角色（此前只有「角色分配菜单」，缺「用户分配角色」）。用户-角色关联表 `sys_user_role` 已存在，需补上写入接口与前端交互。

## 决策

### 1. 角色选择整合进用户新增/编辑弹窗（非独立弹窗）

- 在 `UserFormDialog` 增加「角色」字段（`el-select` 多选），新增、编辑均可见，非必填。
- 理由：角色数量少，整合进表单更轻；避免独立「分配角色」弹窗的交互负担。

### 2. 保存接口复用用户 CRUD，新增两个辅助接口

- `POST /users`、`PUT /users/:id` 增加 `roleIds` 字段，保存时调用 `saveUserRoles` 全量覆盖用户角色。
- 新增 `GET /users/:id/roles`（编辑回显）、`GET /roles/all`（全量角色选项）。
- 理由：用户的新增/编辑本来就是一次性提交，把角色一并带上最自然。

### 3. 超级管理员（R_SUPER）双重保护

- `GET /roles/all` 过滤掉 R_SUPER（下拉里没有，普通用户分不到超管）。
- `saveUserRoles` 全量覆盖时，强制保留用户已有的 R_SUPER（编辑 admin 不会被误清）。
- 理由：R_SUPER 是系统安全底线，只应通过初始化脚本挂载，不应在用户管理里增删。

### 4. 用户列表展示「角色」列

- `getUserList` 联查 `sys_user_role + role`，返回每个用户的角色名数组（`roles`）。
- 前端列表新增「角色」列，用 `el-tag` 渲染（超级管理员红色高亮）。
- 理由：分配了角色却看不到结果，用户无法感知；联查成本低。

## 后果

- 无表结构变更（复用已有 `sys_user_role`）。
- 新增 `GET /roles/all`、`GET /users/:id/roles` 两个接口；`POST/PUT /users` 增加 `roleIds`。
- 用户列表返回结构增加 `roles` 字段，前端表格新增「角色」列。
- `R_SUPER` 不进入用户管理的分配范围（只读、只保留）。
