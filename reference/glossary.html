Monorepo 术语速查表

本文档是 Monorepo 领域的核心术语速查。学新概念时回来翻一翻，帮助巩固记忆。

Monorepo
将多个相关但独立的项目存放在同一个 Git 仓库中的代码管理策略。Mono = 单一，Repo = 仓库。
Polyrepo
Monorepo 的反面——每个项目一个独立的 Git 仓库。也是传统的、最常见的做法。
Workspace（工作区）
包管理器提供的一种机制，允许在一个仓库中定义多个包，并使它们能够互相引用。pnpm 通过 pnpm-workspace.yaml 配置。
Package（包）
Workspace 下的每个独立项目。每个包有自己的 package.json、独立版本号、独立构建产物。
Root Package（根包）
仓库根目录的 package.json，通常设置 "private": true 防止误发布。在此管理全局脚本和共享 devDependencies。
workspace:* 协议
pnpm 特有的依赖协议。声明依赖为 "foo": "workspace:*" 时，pnpm 会从本地工作区解析该包，而不是从 npm registry 下载。
pnpm-workspace.yaml
pnpm 的工作区配置文件，定义哪些目录包含子项目。优先级高于 package.json 中的 workspaces 字段。
pnpm
快速、节省磁盘的包管理器。使用硬链接和符号链接管理 node_modules，天然支持 Workspace。npm/yarn 的替代品。
Turborepo
Vercel 开发的 Monorepo 构建工具。通过任务图（Pipeline）和缓存机制，只构建发生变化的包及其依赖，大幅提速。
Nx
Nrwl 开发的全功能构建系统。功能比 Turborepo 更丰富，包括依赖图可视化、代码生成器、插件系统等。
Lerna
老牌 Monorepo 管理工具，擅长版本管理和发布。现状：常与 Nx 或 Turborepo 配合使用，Lerna 负责发布，另一个负责构建。
Changesets
专注于多包版本管理和 Changelog 生成的工具。比 Lerna 更轻量，是当前社区推荐方案。
Atomic Commit（原子提交）
Monorepo 的核心优势之一：可以一次 git commit 同时修改多个项目，保证改动的一致性，避免多仓库间版本错乱。
幽灵依赖 (Phantom Dependency)
代码中使用了某个包，但没有在 package.json 中显式声明。pnpm 的严格模式可杜绝此问题。
硬链接 (Hard Link)
pnpm 存储依赖的方式：多个项目共享同一份磁盘文件，而不是各自拷贝一份，极大节省磁盘空间。
Filter（过滤）
Monorepo 工具的命令过滤语法。如 pnpm --filter admin run dev 只对 admin 包执行 dev 脚本。
Pipeline（流水线）
Turborepo 中的核心概念。定义任务之间的依赖关系（如 build 之前必须先 build 它的依赖），实现正确且高效的并行执行。
