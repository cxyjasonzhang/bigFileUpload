0. pnpm Workspace 的"短板"

前几课我们用 pnpm Workspace 搞定了依赖共享和类型安全。 但有一个场景会让你抓狂：

改了 shared-utils → pnpm -r run build → 全量重构建 😫

❌ 没有 Turborepo

改 shared-utils 的一行注释 → admin 也完整重构建 → server 也完整重构建。
三个项目，改一行，全部跑一遍。慢。

✅ 有了 Turborepo

改 shared-utils 的一行注释 → 如果产物没变（缓存命中）→ admin 和 server 直接跳过。
三个项目，改一行，零构建。秒出结果。

🎯 Turborepo 解决两个核心问题

① 按依赖顺序构建：如果 admin 依赖 shared-utils，Turborepo 保证先 build shared-utils，再 build admin。
② 缓存：如果某次构建的输入（源码 + 依赖）和上次一模一样，直接复用上次的产物，跳过构建。

1. Turborepo 是什么

一句话

Turborepo 是 Vercel 开源的 Monorepo 构建系统。 它不替代 pnpm（包管理归 pnpm 管），它负责编排任务执行顺序和缓存构建结果。

职责 pnpm Workspace Turborepo
依赖安装 pnpm 管 不管
包间链接 符号链接 不管
任务执行顺序 按字母顺序跑 依赖拓扑排序
构建缓存 无 基于内容的缓存
远程缓存 无 团队共享缓存
并行执行 支持（-r --parallel） 智能并行（按依赖图）

2. 安装 & 配置

1

在根目录安装 turbo

pnpm add turbo -Dw

作为全局开发依赖安装在根目录。-Dw 表示 dev + workspace-root。

2

创建 turbo.json — Turborepo 的核心配置

my-monorepo/turbo.json
{
  "$schema": "https://turbo.build/schema.json",
  "tasks": {
    "build": {
      // 声明 build 依赖了哪些任务的产物
      "dependsOn": ["^build"],
      // 告诉 turbo build 的输出在哪（用于缓存）
      "outputs": ["dist/**", ".next/**"]
    },
    "dev": {
      // dev 不缓存（开发模式总是需要重跑）
      "cache": false,
      "persistent": true
    },
    "test": {
      "dependsOn": ["build"],
      "outputs": ["coverage/**"]
    },
    "lint": {
      // lint 不依赖其他任务的产物
      "outputs": []
    },
    "typecheck": {
      "dependsOn": ["^build"],
      "outputs": []
    }
  }
}
🔑 dependsOn 的两种写法

"dependsOn": ["^build"] — 带 ^ 前缀：先跑这个包所依赖的包的 build。
"dependsOn": ["build"] — 不带 ^：先跑这个包自己的其他任务（用得少）。

👉 这是最重要的概念：^build 意味着"admin 的 build 依赖 shared-utils 的 build"，Turborepo 会先构建 shared-utils，再构建 admin。

3

用 turbo 替代 pnpm 执行任务

修改根目录 package.json 的脚本：

my-monorepo/package.json
{
  "scripts": {
    "dev": "turbo dev",
    "build": "turbo build",
    "test": "turbo test",
    "lint": "turbo lint",
    "typecheck": "turbo typecheck"
  }
}

3. 缓存机制 — Turborepo 的灵魂

Turborepo 的缓存不是"时间到就过期"，而是基于内容哈希的。 每次运行任务时，它会：

  1. 计算所有输入文件的哈希（源码 + 依赖的 package.json）
  2. 拿这个哈希去 .turbo 缓存目录里找
  3. 找到→直接还原产物（CACHE HIT），跳过实际构建
  4. 找不到→执行构建 → 把产物存入缓存（CACHE MISS）
源码文件 → 哈希计算 → CACHE HIT → ⚡ 秒级完成
（无变化时）
🔬 亲自感受一下

运行两次 pnpm build（即 turbo build）：
第一次：所有包全量构建（CACHE MISS）
第二次：全缓存命中（FULL TURBO），可能不到 100ms 就完成！

4. 实战：给已有项目接入 Turborepo

基于第 2-3 课搭好的 my-monorepo 项目，完整接入流程：

1

安装 turbo

cd my-monorepo
pnpm add turbo -Dw
2

创建 turbo.json（基于现有项目）

turbo.json
{
  "$schema": "https://turbo.build/schema.json",
  "tasks": {
    "build": {
      "dependsOn": ["^build"],
      "outputs": ["dist/**"]
    },
    "dev": {
      "cache": false,
      "persistent": true
    },
    "lint": {},
    "typecheck": {
      "dependsOn": ["^build"]
    }
  }
}
3

确保每个子包有 build 脚本

检查各包子包的 package.json，至少要有 build 脚本：

packages/shared-utils/package.json
{
  "scripts": {
    "build": "tsc",
    "typecheck": "tsc --noEmit"
  }
}
apps/admin/package.json（Vite 创建的已有）
{
  "scripts": {
    "dev": "vite",
    "build": "vue-tsc && vite build",
    "preview": "vite preview"
  }
}
4

更新根目录 scripts

package.json
{
  "scripts": {
    "dev": "turbo dev",
    "build": "turbo build",
    "lint": "turbo lint",
    "typecheck": "turbo typecheck"
  }
}
5

跑起来！

pnpm build

终端会显示 turbo 的运行摘要。再跑一次，你会看到熟悉的：

✅ 第二次运行的输出
Tasks:    3 successful, 3 total
Cached:    3 cached, 3 total
  Time:    87ms >>> FULL TURBO

5. turbo 常用命令

turbo build
按 turbo.json 配置执行 build
turbo build --filter=admin
只构建 admin（含它的依赖）
turbo build --force
忽略缓存，强制全量重构建
turbo build --dry-run
预览要执行的任务（不实际执行）
turbo build --graph
生成任务依赖图（可视化！）
turbo daemon status
查看 turbo 守护进程状态
💡 turbo --dry-run 是调试神器

不确定 turbo 会执行什么任务？先 turbo build --dry-run 看一下。 它会列出哪些任务会跑、哪些会走缓存、执行顺序是什么样的，零副作用。

6. 进阶视野：远程缓存

本地缓存已经很爽了，但远程缓存更"不讲武德"——

🌐 什么是远程缓存？

CI（比如你同事的机器）上构建成功后，把缓存上传到云端。
你在本地拉代码后跑 build，直接命中远程缓存，零构建。

Vercel 提供免费的远程缓存服务（需要关联 Vercel 账号）：
npx turbo login → npx turbo link

这就是为什么 Vercel 的 Next.js 项目构建可以那么快的原因之一。

对于入门阶段，本地缓存已经够用。远程缓存是团队协作时才需要考虑的事情， 这里作为视野拓展点到为止。

7. 工具速览：Turborepo vs Nx vs Lerna

特性 Turborepo Nx Lerna
上手难度 低 中高 低
构建缓存 ✅ 基于内容 ✅ 基于内容 ❌ 无内置
远程缓存 ✅ Vercel 免费 ✅ Nx Cloud ❌
代码生成 ❌ ✅ 强大的 generators ❌
依赖图可视化 CLI 文本图 ✅ Web UI ❌
适合场景 前端为主的 Monorepo 大型全栈企业项目 小型包发布管理
推荐指数 ⭐⭐⭐⭐⭐ 入门首选 ⭐⭐⭐ 大团队 ⭐⭐ 已被替代

结论：对于你的 Vue 3 + Node.js 项目，Turborepo 是最佳选择。 配置简单、速度快、和 pnpm 配合丝滑。
