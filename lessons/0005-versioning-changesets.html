0. 场景：你什么时候会头疼版本？

🤔 场景一
你在 shared-utils 里加了一个新函数，admin 和 server 都用了。怎么标记 shared-utils 版本从 1.0.0 升到多少？1.1.0？1.0.1？
😫 场景二
你同时改了 shared-utils（新增功能）和 ui-components（修了个 bug），两个包都要发版，changelog 怎么写？手动维护？
😱 场景三
同事问："上周这个函数怎么突然不能用了？"你翻 git log 翻了半小时才找到是哪次改坏的。
🎯 Changesets 统一解决这三个问题

自动决定版本号（该升 major/minor/patch 不用你纠结）
自动生成 Changelog（每次改了什么一目了然）
原子发布（一次操作发布所有改动的包，不会漏）

1. 版本号规则：Semver 速览

Changesets 的版本升降基于 Semver（语义化版本）：

1.0.0 → 2.0.0 Major（主版本）：不兼容的 API 修改
1.0.0 → 1.1.0 Minor（次版本）：向下兼容的新功能
1.0.0 → 1.0.1 Patch（修订版）：向下兼容的 Bug 修复
改了什么 升哪个版本 changeset 标记
删了一个公开函数 / 改了参数签名 major major
新增了一个工具函数 minor minor
修复了一个计算错误 patch patch
只改了注释/文档/内部重构 不升版本 不创建 changeset

2. Changesets 是什么

一句话

Changesets 是专门为 Monorepo 设计的版本管理和发布工具。 核心思想："在提交代码的同时，记录这次改了什么 → 以后统一算版本、写 changelog"。

它把版本管理拆成三个独立步骤：

Step 1 提交改动时
加一个 changeset
→
Step 2 集中处理
生成版本号
→
Step 3 发布 +
生成 Changelog
💡 对比：不用 Changesets vs 用 Changesets

不用：开发者改完代码 → 手动改 package.json 版本号 → 手动写 changelog → 容易忘、对不齐
用了：开发者改完代码 → pnpm changeset 选版本类型 → 写完提交 → CI 自动算版本、写 changelog

3. 安装 & 初始化

1

安装 Changesets CLI

pnpm add -Dw @changesets/cli
2

初始化（它会在根目录创建 .changeset 目录）

pnpm changeset init

之后项目里多了一个 .changeset/ 目录：

.changeset/
├── config.json      ← 配置文件
└── README.md        ← 说明文档
3

编辑配置文件

.changeset/config.json
{
  "$schema": "https://unpkg.com/@changesets/config@3/schema.json",
  "commit": false,
  "fixed": [],
  "linked": [],
  "access": "restricted",
  "baseBranch": "main",
  "updateInternalDependencies": "patch",
  "ignore": []
}
🔑 关键配置解释
  • "commit": false — changeset 文件不自动 commit（手动提交更可控）
  • "access": "restricted" — 私有包；公开项目改 "public"
  • "updateInternalDependencies": "patch" — shared-utils 升 patch 时，依赖它的包也自动更新引用
  • "baseBranch": "main" — 对比版本变更的目标分支

4. 实战：完整工作流

假设场景：你在 shared-utils 中新增了一个 parseJSON 函数。

1

写完代码后，创建一个 changeset

pnpm changeset

终端会交互式问你三个问题：

🖥️ 终端交互过程
🦋  Which packages would you like to include?
    ◯ @my-monorepo/server
    ● @my-monorepo/shared-utils    ← 空格选中

🦋  Which packages would you like to include?
    ◯ major
    ● minor                         ← 新增功能选 minor

🦋  Please enter a summary:
    > 新增 parseJSON 工具函数       ← 简明描述
2

Changesets 自动生成了一个文件

---
"@my-monorepo/shared-utils": minor
---

新增 parseJSON 工具函数

文件存在 .changeset/ 目录下，文件名是随机哈希（如 purple-dogs-smile.md）。
把它和代码一起 git commit。

3

积累了一段时间后，统一消费所有 changesets

pnpm changeset version

这个命令会：

  • ✅ 读取 .changeset/ 下所有待处理的文件
  • ✅ 自动计算每个包应该升到的版本号
  • ✅ 更新各包 package.json 里的 version
  • ✅ 自动更新 workspace 依赖的版本（如 admin 里 shared-utils 的引用）
  • ✅ 删除已消费的 changeset 文件
4

发布（如果需要发布到 npm）

pnpm changeset publish

如果你的 shared-utils 需要发布到 npm registry（供外部项目使用）， 这个命令会把版本更新过的包发布出去。
对于内部 Monorepo（包只在仓库内使用），可以不执行这一步。

📋 完整工作流总结
写代码
→
pnpm changeset
→
git commit
→
pnpm changeset version
→
pnpm changeset publish

5. 常用场景决策

🔧 改了一个内部函数（外部 API 不变）
不创建 changeset。内部实现变更不影响使用者，版本号不需要变。
🐛 修了一个 bug，但函数签名没变
创建 patch changeset。行为改变了（之前是错的），使用者需要知道。
✨ 新增了一个函数，旧函数完全不受影响
创建 minor changeset。向下兼容的新功能。
💥 改了 formatDate 的返回值类型
创建 major changeset。这是不兼容变更，任何依赖此函数的代码都可能坏掉。
📦 同时改了 shared-utils（minor）和 ui-components（patch）
pnpm changeset 时用空格同时选中两个包，分别选择不同版本级别。
一个 changeset 文件可以包含多个包的版本变更记录。
🤖 想把 changeset 集成到 CI
常见方案：PR 合入 main 时触发 CI → 自动跑 changeset version → 如果有新版本，CI 自动提一个 "Release" PR → 审核后合入 → 触发 changeset publish。

6. Changesets 自动生成的 Changelog 长什么样

执行 pnpm changeset version 后，shared-utils 目录下会自动生成：

packages/shared-utils/CHANGELOG.md（自动生成）
# @my-monorepo/shared-utils

## 1.1.0

### Minor Changes

- 5142f8a: 新增 parseJSON 工具函数

## 1.0.1

### Patch Changes

- a1b2c3d: 修复 formatFileSize 在 0 字节时显示错误的问题

## 1.0.0

### Major Changes

- d4e5f6g: 初始发布，包含 formatDate、formatFileSize、greet、add
💡 比你手写 changelog 好在哪

• 永远不会忘（写代码时顺手加 changeset）
• 格式统一（全项目一个风格）
• 和 git commit 关联（每个条目都有 commit hash）
• CI 友好（可以自动生成 Release Notes）

7. 给根 package.json 加便捷脚本

package.json
{
  "scripts": {
    "dev": "turbo dev",
    "build": "turbo build",
    "lint": "turbo lint",
    "typecheck": "turbo typecheck",
    "changeset": "changeset",
    "version": "changeset version",
    "release": "turbo build && changeset publish"
  }
}

之后直接：

pnpm changeset
创建一个新的 changeset
pnpm version
消费所有 changeset，更新版本号
pnpm changeset status
查看当前有哪些待处理的 changeset
