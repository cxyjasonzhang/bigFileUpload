pnpm Workspace 从零配置 — 搭建你的第一个 Monorepo

📅 2026-07-28
⏱️ 约 20 分钟
🛠️ 动手实战

0. 本课目标

在这一课中，你将从零开始，用 pnpm Workspace 搭建一个 Monorepo 项目，结构如下：

my-monorepo/
├── pnpm-workspace.yaml      ← 核心：声明工作区
├── package.json              ← 根配置
├── apps/
│   ├── admin/                ← Vue 3 前端（Vite）
│   └── server/               ← Node.js 后端
└── packages/
    └── shared-utils/         ← 共享工具包

学完后，你将能够独立创建和配置任意规模的 pnpm Monorepo 项目。

✅ 开始前确认

确保你的环境中有 Node.js ≥ 18 和 pnpm ≥ 8。终端运行 pnpm --version 检查。如果还没装 pnpm： npm install -g pnpm。

1. 初始化根项目

1

创建项目目录并初始化

创建一个空目录作为 Monorepo 的根目录，然后用 pnpm init 生成根 package.json。

mkdir my-monorepo && cd my-monorepo
pnpm init

编辑 package.json，确保设置 "private": true（防止根目录被误发布到 npm）：

my-monorepo/package.json
{
  "name": "my-monorepo",
  "version": "1.0.0",
  "private": true,
  "description": "我的第一个 Monorepo 项目"
}
⚠️ private: true 很重要

根目录的 package.json 不是给 npm 发布的，它是给 pnpm 用的"组织者"。 忘记加 "private": true 可能导致误 pnpm publish。

2. 创建 pnpm-workspace.yaml

2

这是 Monorepo 的"核心配置文件"

pnpm-workspace.yaml 告诉 pnpm 哪些目录包含子项目（包）。没有它，pnpm 就不知道这是一个 Monorepo。

my-monorepo/pnpm-workspace.yaml
packages:
  - 'apps/*'        # apps 目录下的所有一级子目录
  - 'packages/*'    # packages 目录下的所有一级子目录
💡 配置语法说明
  • 'apps/*'：匹配 apps/ 下的所有一级子目录（如 apps/admin、apps/server）
  • 'packages/**'：匹配 packages/ 下的所有子目录（包括嵌套）
  • '!**/test/**'：排除匹配（感叹号开头表示排除）

3. 创建子项目（Package）

3

创建三个子包：admin、server、shared-utils

① 共享工具包 — packages/shared-utils

mkdir -p packages/shared-utils/src
cd packages/shared-utils && pnpm init
packages/shared-utils/package.json
{
  "name": "@my-monorepo/shared-utils",
  "version": "1.0.0",
  "private": true,
  "main": "./src/index.ts",
  "types": "./src/index.ts"
}
packages/shared-utils/src/index.ts
/** 共享工具函数 */

/** 格式化问候语 */
export function greet(name: string): string {
  return `你好，${name}！欢迎来到 Monorepo。`;
}

/** 两数相加 */
export function add(a: number, b: number): number {
  return a + b;
}

② Vue 3 前端应用 — apps/admin

用 Vite 快速创建 Vue 3 项目：

pnpm create vite apps/admin --template vue-ts
💡 关于 apps/admin/package.json

Vite 脚手架会自动生成 package.json，其中 name: "admin"。 你也可以改成 "@my-monorepo/admin"，保持命名统一。当前用默认名也没问题。

③ Node.js 后端应用 — apps/server

mkdir -p apps/server/src
cd apps/server && pnpm init
apps/server/package.json
{
  "name": "@my-monorepo/server",
  "version": "1.0.0",
  "private": true,
  "main": "./src/index.js",
  "scripts": {
    "dev": "node --watch src/index.js",
    "start": "node src/index.js"
  }
}
apps/server/src/index.js
const http = require('http');

const server = http.createServer((req, res) => {
  res.writeHead(200, { 'Content-Type': 'application/json' });
  res.end(JSON.stringify({ message: 'Hello from Monorepo server!' }));
});

server.listen(3000, () => {
  console.log('Server running at http://localhost:3000');
});

4. 安装依赖 — 见证 pnpm 的魔法

4

回到根目录，一条命令安装所有子项目的依赖

cd my-monorepo
pnpm install

pnpm 会：

  • 扫描 pnpm-workspace.yaml 找到所有子项目
  • 分别安装每个子项目 package.json 中的依赖
  • 用硬链接存储，相同的包在磁盘上只存一份
  • 为 workspace 内的包建立符号链接，让它们能互相引用
🔬 验证一下

运行 pnpm list --depth=0 -r 可以查看所有子项目的依赖。
你会发现 node_modules 里出现了以 @my-monorepo 开头的 符号链接（symlink），指向工作区内的其他包。

5. workspace:* 协议 — 本地包互相引用

5

让 server 引用 shared-utils

不需要发布到 npm、不需要 npm link，只需要一条命令： 

pnpm add @my-monorepo/shared-utils --filter @my-monorepo/server

这会在 apps/server/package.json 中添加：

apps/server/package.json（自动更新后）
{
  "dependencies": {
    "@my-monorepo/shared-utils": "workspace:*"
  }
}
🔍 workspace:* 是什么意思？

workspace:* 是 pnpm 特有的协议（protocol）。 它告诉 pnpm："这个包就在当前工作区里，不要去 npm registry 下载"。 pnpm 会把 @my-monorepo/shared-utils 软链接到 packages/shared-utils 的实际目录。

常用的 workspace 协议写法：
workspace:* — 直接用工作区最新版
workspace:^1.0.0 — 要求匹配 1.x.x 版本
workspace:./packages/shared-utils — 用相对路径指定（较少用）

6. 统一脚本 — 一键运行所有项目

6

在根目录的 package.json 中添加统一脚本

my-monorepo/package.json
{
  "name": "my-monorepo",
  "version": "1.0.0",
  "private": true,
  "scripts": {
    "dev": "pnpm -r --parallel run dev",
    "build": "pnpm -r run build",
    "dev:admin": "pnpm --filter admin run dev",
    "dev:server": "pnpm --filter @my-monorepo/server run dev"
  }
}
📖 命令参数速查
pnpm -r run dev
递归执行所有包的 dev 脚本
pnpm --filter admin run dev
只对 admin 包执行 dev
pnpm -r --parallel run dev
并行运行所有包的 dev 脚本
pnpm add lodash -w
给根项目安装依赖（-w 允许）
pnpm add axios --filter server
给 server 包安装 axios
pnpm -r update
更新所有包的依赖
⚠️ 易错点

在根目录直接 pnpm add xxx 会报错（因为 private: true）， 需要加 -w（--workspace-root）才可以给根项目装依赖。 通常只在根目录装 开发工具（TypeScript、ESLint、Prettier 等全局配置）。

7. 完整项目结构回顾

my-monorepo/
├── pnpm-workspace.yaml         ← pnpm：这些是我的子项目
├── package.json                ← root: private + 统一脚本
├── pnpm-lock.yaml              ← 全局锁文件
├── node_modules/               ← 所有包的依赖（硬链接）
│   └── @my-monorepo/           ← 工作区内部链接（符号链接）
│       ├── shared-utils  →  ../../packages/shared-utils
│       └── server        →  ../../apps/server
│
├── apps/
│   ├── admin/                  ← Vue 3 + Vite 前端
│   │   ├── package.json
│   │   ├── vite.config.ts
│   │   ├── tsconfig.json
│   │   └── src/
│   └── server/                 ← Node.js 后端
│       ├── package.json        ← 依赖了 @my-monorepo/shared-utils
│       └── src/
│           └── index.js
│
└── packages/
    └── shared-utils/           ← 共享工具
        ├── package.json        ← name: @my-monorepo/shared-utils
        └── src/
            └── index.ts
