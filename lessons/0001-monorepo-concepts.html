1. 先看看你熟悉的场景

假设你要做一个全栈项目：一个 Vue 3 管理后台 + 一个 Node.js API 服务， 还有一些共用代码（比如工具函数、类型定义、UI 组件）。

最常见的做法是 Polyrepo（多仓库）——每个项目各自一个 Git 仓库：

🔴 Polyrepo（多仓库）

# 仓库 1: admin-frontend
admin-frontend/
  src/
  package.json
  tsconfig.json
# 仓库 2: api-server
api-server/
  src/
  package.json
# 仓库 3: shared-utils
shared-utils/
  src/
  package.json
  (要发布 npm 或 npm link)

🟢 Monorepo（单仓库）

# 一个仓库管理全部
my-project/
  pnpm-workspace.yaml
  package.json
  apps/
    admin/
    server/
  packages/
    shared-utils/
    ui-components/

💡 一句话理解 Monorepo

Polyrepo 就像 三个独立的小区，各有各的大门和物业，想串个门很麻烦。
Monorepo 则是 一栋大楼里的三个楼层，共享水电、电梯和走廊，串门只需要走楼梯。

2. Monorepo 到底是什么？

📖 官方定义

Monorepo（Mono = 单一，Repo = 仓库）是一种代码管理策略，将 多个相关但独立的项目存放在 同一个 Git 仓库中统一管理。

它与"把代码放一起"有本质区别——Monorepo 的核心是：

  • 每个项目仍是独立的包（有自己的 package.json）
  • 通过 Workspace（工作区）机制让它们能互相引用
  • 统一工具链（一份 ESLint/TypeScript 配置管全部）
  • 原子提交（一次 commit 可以同时改前端和后端）
⚠️ 常见误解

Monorepo ≠ 把所有代码扔进一个巨型项目。每个子项目有独立构建、独立版本、独立职责。 它更像是住在同一个小区里的独立住户，而不是住在同一个房间里。

3. Monorepo vs Polyrepo — 一张表看懂

维度 Polyrepo（多仓库） Monorepo（单仓库）
代码共享 需要发布 npm 包或用 npm link，流程繁琐 直接用 workspace:* 引用，和引用本地文件一样简单
跨项目改动 需要分别提 MR/PR，容易遗漏、版本错乱 一次 commit 覆盖所有相关改动，原子操作
依赖管理 每个仓库各自 npm install，版本可能不一致 根目录统一安装，pnpm 用硬链接去重，省磁盘
CI/CD 各自独立流水线，配置分散 统一流水线 + 按变更范围智能构建（需要工具支持）
权限控制 天然隔离，不同团队只能看自己的仓库 需要在仓库内部做目录级权限（或使用 CODEOWNERS）
上手难度 简单直观，一个项目一个仓库 需要学习 Workspace 配置和 Monorepo 工具链
适合场景 项目完全独立、无共享代码、不同团队 有共享包的关联项目、微前端、组件库 + 应用

4. 核心术语速览

Workspace（工作区）

告诉包管理器"哪些目录是子项目"的配置。pnpm 通过 pnpm-workspace.yaml 定义。 Workspace 内的包可以互相引用，就像在一个小型的本地 npm registry 里。

Package（包）

Workspace 下的每个子项目都是一个包。每个包有自己的 package.json， 独立构建、独立版本。包名通常用作用域前缀，如 @my-project/shared-utils。

Root package（根包）

仓库根目录的 package.json，通常设置 "private": true（防止误发布）。 在这里管理全局工具（TypeScript、ESLint）和统一脚本。

workspace:* 协议

pnpm 特有的依赖协议。当包 A 依赖包 B 时，用 "@my-project/b": "workspace:*" 告诉 pnpm："从本地工作区解析，不要去 npm registry 下载"。

5. 一个典型的 Monorepo 长什么样

my-monorepo/
├── pnpm-workspace.yaml      ← 定义哪些目录是子项目
├── package.json              ← 根配置（private: true）
├── tsconfig.base.json        ← 共享 TypeScript 配置
├── .eslintrc.js              ← 共享 ESLint 配置
├── pnpm-lock.yaml            ← 全局锁文件
│
├── apps/                     ← 应用（可独立部署）
│   ├── admin/                ← Vue 3 管理后台
│   │   ├── package.json
│   │   ├── vite.config.ts
│   │   └── src/
│   └── server/               ← Node.js API 服务
│       ├── package.json
│       └── src/
│
└── packages/                 ← 共享库（被 apps 引用）
    ├── shared-utils/         ← 工具函数
    │   ├── package.json      ← name: "@my-project/shared-utils"
    │   └── src/
    └── ui-components/        ← 共享 UI 组件
        ├── package.json      ← name: "@my-project/ui-components"
        └── src/
📐 目录命名约定

apps/：可独立运行、部署的应用（前端页面、后端服务、小程序等）
packages/：被引用的共享库（工具、组件、类型、配置等）
这是社区广泛采用的约定，不是强制规则。

6. 工具生态一览

工具 职责 一句话
pnpm Workspace 包管理 + 依赖管理 Monorepo 的地基，管依赖和链接
Turborepo 任务编排 + 缓存 让构建和测试只跑改了的部分
Nx 全功能构建系统 比 Turborepo 更重，带依赖图可视化和代码生成
Lerna 版本管理 + 发布 老牌工具，现在常和 Nx/Turborepo 配合使用
Changesets 版本管理 + Changelog 管理多包的版本发布和变更日志

对于入门来说，pnpm Workspace 就够用了。涡轮增压（Turborepo）是加分项，后面再学。
